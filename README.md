# otp-relay — 手机验证码自动到 Mac 剪贴板

投简历/登录时不用再"掏手机 → 看短信 → 手抄验证码"。
手机收到验证码短信后自动转发到本机，抠出验证码、**写入 Mac 剪贴板并弹通知**，你在网页里 `Cmd+V` 即可。

## 它是怎么工作的

```
手机（收到含"验证码"的短信）
   │  POST http://<Mac的IP>:8787/otp   body: 短信原文
   ▼
同一个 Wi-Fi / 手机热点（局域网直连，无需公网、无需 VPN）
   ▼
Mac 上的 otp_server.py（监听 8787，路由 /otp）
   │  以"验证码/code"为锚抠出 4-8 位数字 → 写剪贴板 + 弹通知
   ▼
你在网页里 Cmd+V
```

- **不改机器人自动投递**，只是半自动：省掉"掏手机看码抄码"，保留你手动 `Cmd+V`。
- **零依赖**：只用 macOS 自带的 `python3` / `pbcopy` / `osascript`。

---

## Mac 端：启动服务

```bash
cd otp-relay
./start.sh
```

`start.sh` 会**自动探测本机 IP**，并打印出"手机该填的 URL"，例如：

```
📱 在手机上把转发地址填成：
        http://192.168.1.23:8787/otp
```

把这个 URL 记下来，配到手机端（见下）。窗口别关，服务要一直开着。

> 换网络后 Mac 的 IP 会变，重跑 `./start.sh` 拿到新地址、更新手机端即可。

## 手机端

手机侧只当"哑巴转发器"：**收到含"验证码"的短信 → 把原文 POST 到上面那个 URL**。抠码逻辑全在 Mac，手机不用管。

### iPhone（快捷指令，iOS 16+）

1. 快捷指令 App → **自动化** → **＋** → 新建自动化
2. 触发选 **信息**：发件人=任何人，信息**包含** `验证码`，运行方式=**立即运行**（关掉"运行前询问"）
3. 加动作 **获取 URL 内容**：
   - URL：`http://<Mac的IP>:8787/otp`
   - 展开"显示更多"：方法 **POST**，请求体 **JSON**，加字段 `text` = 变量「**快捷指令输入**」（即短信正文）
4. 保存

### Android（没有快捷指令，用短信转发 App）

安卓没有"快捷指令"，用一个支持 Webhook 的短信转发 App 即可。推荐开源免费的
**SmsForwarder（短信转发器）**（GitHub: `pppgao/SmsForwarder`），也可用 **MacroDroid**。

> 服务端容错很强：只要 POST 的 body 里**包含短信正文**（不管纯文本还是 JSON），
> 就能抠出验证码。所以转发 App 的模板**不用调得很精确**，用它的默认模板通常就行。

以 **SmsForwarder** 为例：

1. 安装后按引导授予**短信读取/接收**权限；并在系统里给它**关闭电池优化 / 允许后台常驻**（否则锁屏后可能收不到、转不出）。
2. 进 **发送通道（Senders）** → 新增 → 类型选 **Webhook**：
   - **WebHook 地址**：`http://<Mac的IP>:8787/otp`
   - **请求方式**：`POST`
   - **消息模板 / Body**：用它默认的（含短信正文的那个）即可；想更干净可填 `{"text":"[短信正文变量]"}`（变量名以 App 里给的占位符为准，能带出正文即可）
   - 保存后点**测试**，Mac 终端应打印 `[HIT]`（测试文本里带上"验证码 123456"就能看到）
3. 进 **转发规则（Rules）** → 新增：
   - **匹配字段**：短信内容
   - **匹配方式**：包含 → 关键词 `验证码`（与 iPhone 触发词对等，挡掉私人短信）
   - **发送通道**：选上一步建的 Webhook
   - 保存启用

MacroDroid 方案：触发器=**收到短信** → 动作=**HTTP Request**（POST，URL 同上，Body 放短信内容变量），可加"内容包含 验证码"的约束。

## 验证是否打通（分层排查）

1. **Mac 自测**：服务启动后，`curl http://127.0.0.1:8787/otp -d '{"text":"验证码 123456"}'`，剪贴板应变成 `123456`。
2. **网络自测**：手机 Safari 打开 `http://<Mac的IP>:8787/`，看到 `otp-relay ok` = 手机能连到 Mac。
3. **全链路**：发一条真验证码短信 → Mac 终端打印 `[HIT] code=...` + 弹通知 + 剪贴板就位。

## 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 看不到日志、收不到码 | 服务没在跑（`lsof -iTCP:8787` 查），或手机 URL 的 IP 过时了（重跑 `start.sh`） |
| 手机 Safari 打不开健康页 | 手机和 Mac 不在同一网络；或用了热点但开了客户端隔离 → 改连同一个普通 Wi-Fi |
| 返回 404 | URL 把 `/otp` 写成了 `/opt` |
| 抠到的是手机尾号/订单号 | 已按"关键词为锚"修复；若仍误抓，把样例短信发我调规则 |
| 码对了但没弹通知 | 系统设置→通知里放行终端/脚本（不影响剪贴板，Cmd+V 照用） |
| 英文验证码不触发 | 第一版触发词只配了"验证码"；再建一条触发词 `code` 的自动化 |
| 安卓锁屏后收不到/不转发 | 转发 App 被系统后台省电杀了 → 系统设置里关掉它的电池优化、允许后台常驻/自启动 |

## 配置项（otp_server.py 顶部）

- `PORT`：默认 `8787`
- `TOKEN`：默认空=不校验。填一串随机字符后，手机端需加 Header `X-Token: 该值`
- `KEYWORDS`：命中才当验证码处理的关键词列表
